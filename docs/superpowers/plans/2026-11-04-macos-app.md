# Pod macOS Implementation Plan

**Goal:** Build and show a usable native application around the own Zig PDF engine.
**Architecture:** Zig C ABI and owned CPU bitmap output; AppKit window and file workflow.
**Tech stack:** Zig 0.17.1, Swift 6, AppKit, no external PDF dependency.

- [x] Implement `src/font.zig` bounded TrueType outline decoding and `src/render.zig` CPU rendering, with content state/display-list extensions and tests. Verify known geometry, text, malformed input, unsupported states and transformed runs.
- [x] Implement `src/c_api.zig`, `macos/PodBridge.h` and static library build. Test open/render/edit/save/reopen using the C entrypoints, invalid indices and error handling.
- [x] Build `macos/Engine.swift`, `macos/PodApp.swift`, `macos/PageCanvas.swift` for asynchronous loading/rendering, inspector editing, navigation, zoom, undo/redo and save-copy behavior. Use real engine calls only.
- [x] Add a generated two-page sample, `script/build_and_run.sh`, bundle metadata and Codex Run action. Compile with Swift optimization and Zig safe mode.
- [x] Run existing and new tests; independent PDF reader verifies saved text. Launch the application, inspect actual UI, exercise edits and errors, inspect the rendered native UI. Record binary and bundle size and document compatibility boundaries.
- [x] Review specification coverage then code quality, resolve defects, integrate to main checkout and show app to user.
